# 실적 발표 실시간 번역 자막 앱 — 설계

작성일: 2026-11-04

## 1. 의도와 이유

사용자는 미국 기업의 실적 발표 콜(earnings call)을 브라우저로 듣는데, 영어 실력이 부족해 내용을 따라가기 어렵다. 이 앱은 브라우저에서 나오는 오디오만 받아와 영어를 받아 적고, 로컬 Gemma 4로 한국어로 번역해 별도 창에 대본 형태로 보여준다.

실적 발표 콜의 특징:
- 30~60분 길이이며, 경영진 발표 후 애널리스트 질의응답이 이어진다.
- 매출, EPS, 마진, 가이던스 같은 숫자와 재무 용어가 빠르게 쏟아진다.

**사용자에게 가장 중요한 것은 숫자와 실적 용어의 정확성이다.** 몇 초 늦게 뜨는 것은 괜찮다(사용자 확인).

## 2. 목표

1. 사용자가 고른 브라우저의 오디오만 캡처한다. 영상과 화면은 캡처하지 않는다.
2. 영어 음성을 받아 적고, 문장 단위로 한국어 번역을 보여준다.
3. 숫자와 재무 용어를 정확하게 번역한다. 정확성을 확신할 수 없는 문장은 사용자에게 눈에 띄게 표시한다.
4. 대본을 마크다운 파일로 저장한다.
5. 모든 처리를 맥 안에서 한다. 번역은 Ollama의 Gemma 4가 맡는다.

## 3. 비목표

- 번역 결과를 음성으로 읽어주기(TTS/더빙). 자막만 필요하다(사용자 확인).
- 영상을 앱 안에 띄우기. 앱은 별도 창이고, 영상은 브라우저에서 그대로 본다(사용자 확인).
- 화자 구분(CFO, 애널리스트 등)은 첫 버전에서 뺀다. 로컬에서 정확하게 하기 어렵기 때문이다. *(내 판단, 사용자에게 알렸고 반대는 없었음)*
- 영어→한국어 외의 언어 조합.
- App Store 배포, 다른 사람에게 배포하기 위한 공증(notarization).

## 4. 반목표 (돌아가더라도 실패로 보는 경우)

- **숫자가 조용히 틀리는 것.** 예를 들어 "$94.9 billion"을 "94억 9천만 달러"로 옮기거나, 퍼센트와 베이시스포인트를 헷갈리거나, 분기나 연도를 바꿔 쓰는 경우. 틀릴 수 있다면 반드시 경고를 띄워야 한다.
- 오디오나 대본이 맥 밖으로 나가는 것(클라우드 API, 원격 모델, `gemma4:cloud` 태그 사용 금지).
- 시간이 지날수록 지연이 계속 쌓여서 콜이 끝날 무렵 몇 분씩 뒤처지는 것.

## 5. 제약

- 하드웨어: Apple M4, 통합 메모리 24GB, macOS 27.2, 디스크 여유 139GB.
- 설치된 도구: Ollama(`/opt/homebrew/bin/ollama`), Swift 6.4 툴체인(Command Line Tools). **Xcode 앱은 없다.**
- Ollama의 Gemma 4는 텍스트와 이미지 입력만 지원하고 오디오 입력은 지원하지 않는다(ollama.com/library/gemma4 확인). 따라서 음성 인식은 별도 단계가 필요하다.
- 사용 가능한 Gemma 4 태그: `e2b`(4.6GB), `e4b`(6.6GB), `12b`(7.7GB), `26b`(16GB, MoE a4b), `31b`(19GB).
- 같은 맥에서 브라우저와 영상 재생이 함께 돌아간다.

## 6. 결정된 사항

### 사용자가 정한 것
- 출력은 자막만 한다.
- 화면은 **B안: 별도의 세로형 대본 창**. 문장마다 영어 원문을 작고 흐리게, 그 아래 한국어 번역을 크게 보여준다. 새 문장이 아래에 쌓인다.
- 앱은 브라우저와 별개의 창이고, 브라우저의 오디오만 받아온다.
- 대본을 파일로 저장한다.
- 숫자와 실적 용어는 정확해야 한다.
- 몇 초 정도의 지연은 괜찮다.
- 번역 모델은 로컬 Gemma 4.
- **주 사용 브라우저는 Chrome.** 첫 동작 확인(오디오 캡처)은 Chrome으로 한다. 다른 브라우저는 그다음이다.
- **받아쓰기 엔진은 처음에 맥 내장 음성 인식 하나만 쓴다.** 음성 인식이 숫자를 잘못 듣는 경우를 잡는 장치는 첫 버전에 넣지 않는다. 실제 콜에서 숫자를 자주 틀리면 그때 보강한다. 따라서 ⚠는 "번역이 영어 원문과 다를 수 있음"을 뜻하고, "영어로 받아 적은 숫자가 틀렸을 수 있음"은 뜻하지 않는다. 이 의미를 앱 안의 도움말(⚠에 마우스를 올리면 나오는 설명)에 적는다.

### 내 판단 (사용자에게 설명함, 명시적 동의는 아님)
- **네이티브 맥 앱, Swift + SwiftUI.**
- **처리 흐름:** 브라우저 오디오 캡처 → 맥 내장 온디바이스 음성 인식(영어 받아쓰기) → Ollama Gemma 4 번역 → 대본 창.
- **창:** 항상 위에 떠 있기(켜고 끌 수 있음). 자동 스크롤을 하되, 사용자가 위로 스크롤하면 자동 스크롤을 멈추고 "최신으로" 버튼을 보여준다. 지금 진행 중인 문장은 강조 표시한다. 영어가 먼저 뜨고 한국어는 번역이 끝나면 채워진다.
- **상단 바:** 시작/정지 버튼, 캡처할 브라우저 선택, 저장 버튼.
- **저장:** 마크다운(.md). 문장마다 시각(콜 시작 기준 `HH:MM:SS`), 영어 원문, 한국어 번역을 넣는다. 파일 이름은 `YYYY-MM-DD_HHMM.md`. 저장 폴더는 처음에 한 번 고르고 기억한다. 녹음 중에는 몇 초마다 자동 저장해서 앱이 종료돼도 내용이 남게 한다.

### 이 문서에서 정하는 기술 결정 (내 판단)

**오디오 캡처: Core Audio process tap** (`AudioHardwareCreateProcessTap`, macOS 14.2+)
- 선택한 브라우저 프로세스의 오디오만 가져온다. 화면 녹화 권한 없이 "시스템 오디오 녹음" 권한만 필요해서 사용자가 원하는 "오디오만"과 맞는다.
- Chrome은 소리를 helper나 오디오 서비스 프로세스에서 낸다. 그래서 메인 프로세스 하나가 아니라 **Chrome 앱의 모든 하위 프로세스를 대상으로 해야 한다.** 이것이 가장 큰 초기 위험 요소이므로 **구현의 첫 단계로 Chrome 오디오 캡처를 확인한다.**
- 탭은 브라우저 소리를 가로채지 않는다(사용자는 계속 소리를 듣는다).
- 대상 브라우저 목록: 현재 실행 중이면서 오디오를 낼 수 있는 앱(Chrome, Safari, Arc, Edge, Firefox, Whale 등)을 보여준다.

**음성 인식: Apple `SpeechAnalyzer` + `SpeechTranscriber`** (macOS 26+, 온디바이스, en-US)
- 중간 결과(volatile)는 진행 중인 문장 줄에 영어로 바로 보여주고, 확정 결과(final)가 나오면 번역으로 넘긴다.
- 영어 음성 모델 에셋은 처음에 한 번 내려받아야 할 수 있다. 앱이 내려받기를 안내하고 진행 상황을 보여준다. 이것은 오디오가 아닌 모델 파일이므로 "데이터가 맥 밖으로 나가지 않는다"는 원칙에 어긋나지 않는다.
- 확정 문장이 너무 길면(예: 40단어 이상) 구두점을 기준으로 나눠서 번역한다.

**번역: Ollama HTTP API** (`http://localhost:11434/api/chat`)
- 기본 모델은 **`gemma4:12b`**. 24GB 맥에서 브라우저와 음성 인식을 함께 돌려도 여유가 있다. 설정에서 `e4b` / `26b`로 바꿀 수 있다. 구현 초반에 실제 실적 발표 문장으로 `12b`와 `26b`의 속도와 정확성을 비교해 보고 기본값을 확정한다.
- `temperature: 0`, `keep_alive`을 충분히 길게 잡아 콜 도중 모델이 내려가지 않게 한다.
- 매 요청에 시스템 프롬프트(재무 번역 규칙), 용어집, 직전 2~3문장의 원문/번역(맥락 유지용)을 함께 보낸다.
- 번역 요청은 순서대로 처리한다. 대기열이 일정 길이 이상 밀리면 화면에 "번역 지연 중" 상태를 보여준다(반목표 3 참고).
- **밀릴 때의 원칙 (내 판단):** 모든 문장은 빠짐없이 번역한다(저장 파일이 완전해야 함). 대기열에 여러 문장이 쌓이면 한 번의 요청에 묶어 보내 따라잡는다. 응답은 문장별로 나눠 받을 수 있는 형식(예: 번호가 붙은 JSON 배열)으로 받는다. 묶음 번역에도 숫자와 용어 검증을 문장마다 적용한다. Ollama가 꺼졌다가 돌아온 뒤 밀린 문장을 처리할 때도 같은 방식으로 한다.

**숫자 정확성 장치**
1. **프롬프트 규칙:** 숫자는 한국어 단위로 정확히 바꾼다(billion → 10억 단위, 예: $94.9 billion → 949억 달러). %, bp, 분기(Q3 → 3분기), 회계연도(FY2026 → 2026 회계연도), 통화를 그대로 지킨다. 말하지 않은 숫자를 덧붙이지 않는다.
2. **용어집:** 실적 발표 용어 사전을 기본으로 넣는다(EPS → 주당순이익(EPS), guidance → 가이던스, year over year → 전년 대비, basis points → bp, operating margin → 영업이익률, free cash flow → 잉여현금흐름, headwinds/tailwinds → 역풍/순풍, beat/miss → 예상치 상회/하회 등). 사용자가 고칠 수 있도록 앱 지원 폴더의 JSON 파일로 둔다.
3. **자동 검증:** 영어 원문과 한국어 번역에서 각각 숫자를 뽑아 값으로 정규화한 뒤 비교한다. 영어는 숫자, million/billion/trillion, percent, basis points, 숫자를 말로 쓴 경우를 처리한다. 한국어는 만/억/조, %, bp를 처리한다. 값이 다르면 한 번 다시 번역하고, 그래도 다르면 그 문장 옆에 **⚠ 표시**를 붙인다. 원문은 바로 위에 있으므로 사용자가 직접 확인할 수 있다. 저장 파일에도 ⚠를 남긴다.
4. **용어 검증 (내 판단):** 원문에 용어집의 영어 용어가 있는데 번역에 정해 둔 한국어 표현이 없으면, 숫자 불일치와 똑같이 처리한다(한 번 다시 번역하고, 그래도 없으면 ⚠). 영어 쪽은 대소문자와 단수/복수를 구분하지 않는다.
5. **분기·연도·말로 한 숫자:** "first quarter" → 1분기, "fiscal twenty-six" → 2026 회계연도, "Q3" → 3분기, "mid-single digits" 같은 표현을 정규화 규칙에 넣어 숫자 비교에 포함한다.
6. 이 검증기들은 단위 테스트로 충분히 다룬다(실적 발표 문장 예시 다수).

**빌드와 패키징**
- Xcode 앱이 없으므로 **Swift Package(SwiftPM)로 빌드하고, 스크립트로 `.app` 번들을 만든다.** 번들에는 `Info.plist`(권한 설명 문구 `NSAudioCaptureUsageDescription`, `NSSpeechRecognitionUsageDescription` 포함)를 넣고 ad-hoc 서명을 한다. 권한 요청이 제대로 뜨려면 `.app` 번들로 실행해야 한다.
- 최소 지원 OS는 macOS 26.

**오류 상황**
- Ollama가 꺼져 있거나 모델이 없으면: 대본 창에 명확한 안내를 보여준다("Ollama 실행 필요", "`ollama pull gemma4:12b` 필요"). 받아쓰기는 계속하고, 번역은 Ollama가 돌아오면 밀린 문장부터 이어서 한다.
- 권한이 거부되면: 시스템 설정의 어디를 열어야 하는지 안내한다.
- 선택한 브라우저가 종료되면: 녹음을 멈추고 저장한다.

## 7. 빌더에게 맡기는 것

- 코드 구조, 모듈 나누기, 동시성 모델(Swift Concurrency 사용을 권장).
- 오디오 포맷 변환(탭 출력 → 음성 인식 입력 포맷).
- 자동 저장 주기(대략 5초 내외), 대기열 지연 임계값.
- 프롬프트의 정확한 문구, 맥락으로 넘길 문장 수 조정.
- 창의 세부 디자인(글꼴 크기, 색). 시안 B의 구조만 지키면 된다. 다크 모드를 지원한다.
- 테스트 방식. 권장: 녹음된 실적 발표 오디오 파일을 파이프라인에 넣어 끝까지 돌리는 재생 테스트, 그리고 숫자 검증기 단위 테스트.
- 음성 인식 품질이 실적 발표에 부족할 경우 WhisperKit 같은 대안 검토. 바꾸기 전에 사용자에게 알린다.
